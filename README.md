# Atoms Lab

一个可以在本地或云端完整运行的 Atoms 风格 AI 工作室：用一句话描述产品，八位智能体角色通过**真实的流式模型调用**分工协作，编译出可点击的网页，再预览、修改、点选改写、发布并统计真实浏览量。

## 运行

需要 Node.js 22.13 或更新版本。零依赖，不需要 `npm install`。

```bash
npm start
# 或指定端口
PORT=8080 npm start
```

打开 http://localhost:4173

模型接口（兼容 OpenAI 的 `chat/completions`）在「设置」页配置，或直接用环境变量注入：

```
ATOMS_LLM_BASE=https://api.deepseek.com/v1
ATOMS_LLM_MODEL=deepseek-chat
ATOMS_LLM_KEY=sk-xxx
```

没有配置密钥时，应用会明确告知“无法生成”，**不会用模板内容冒充模型输出**。

`npm run check` 会用一份模型返回的样例检查结构、依据是否真的出现在页面里、以及不合格返回会被拒绝。它不会联网。

数据写在 `data/atoms.sqlite`（SQLite，WAL 模式）。删掉这个文件就会回到全新状态。

## 核心体验

1. **流式多智能体编译**：发送需求后，八位角色（Mike/Iris/Emma/Bob/Alex/Sarah/David/Adrian）的结论经 **SSE 实时推送**逐个出现。数据来自两次真实模型调用：先定向（Mike+Iris+Emma），再编译（Bob+Alex+Sarah+David+Adrian）。任一阶段失败会降级为单次完整调用，生成仍可完成。
2. **依据必须可核对**：每位角色的“依据”必须是页面正文里的原句，服务端逐字校验，对不上就整版丢弃。点「定位到页面」预览会滚动并高亮那句。
3. **九类可交互页面**：落地页、品牌站、网店、预约、后台、任务板、博客、小游戏、推荐平台。预约要选服务/日期/时间后才有回执，网店有购物袋和演示结算，任务板刷新后还在，小游戏记最高分。
4. **继续修改 → 改动清单**：追加一句话会生成新版本，并自动对比新旧 DOM，聊天里出现“这次改了 N 处”的清单，点一条就在预览里定位。
5. **点选元素让 AI 改写**：在预览里点任何标题或段落，写一句要求（如“更短，并强调今天截止”），模型改写这一句并写入新版本；也可以切「手动改字」直接编辑。
6. **竞赛模式**：一次给出三套配色和版式（真实三次渲染），选定后才能发布。
7. **发布 + 真实浏览统计**：发布得到 `/p/...` 独立链接，每次被打开都在 SQLite 里按天计数，工作室有过去 7 天的柱状图——不是演示数据。
8. **探索页**：所有已发布应用按真实浏览量出现在 `/explore`。
9. **积分与演示套餐**：生成 15、竞赛 30、修改 8，注册赠 120；余额、流水持久化在 SQLite。
10. **设置页可“测试连接”**：用一次真实的小请求验证接口、模型和密钥，显示耗时。
11. **生成后自动交互自检 + 版式体检**：每一版编译完成后，工作室会把该版页面克隆到隐藏沙箱里，真实点击每一个按钮、提交每一个表单（MutationObserver 判定是否有真实 DOM 响应），再把窗口缩到 390px 检查横向溢出与出屏元素——「✓ 手机版无横向溢出」这样的体检结果作为一条消息持久化进对话流，不可用的交互和版式问题都会标 ✗，团队自己先验收，再交给你验收。编译产物自带手机端断点样式，标题在窄屏保持单行。
12. **发布页会收集真实访客反馈**：每个发布链接右下角有「有用」按钮，访客点赞写入 SQLite 并回显在工作室的统计面板里；点赞过的浏览器本地防重。
13. **探索页可一键复刻（Remix）**：任何已发布应用都能「复刻这个想法」——把原作者的原始提示词装进你自己的项目，走同一条八角色流水线重新生成；未登录会先引导注册，登录后自动开跑。
14. **Sarah 的交付可视化**：发布统计面板里有「搜索结果预览」卡片，用模型写出的 SEO 标题/描述渲染成搜索引擎结果的样子，SEO 角色的产出不再是黑盒。
15. **画廊即证据**：首页「能构建什么」的六个模块卡片，直接内嵌模型真实编译的示例页（缩放后的活 iframe），不是设计稿也不是截图；点开全尺寸后里面的按钮、表单、小游戏都能真实操作。示例在服务端按需真实编译并持久缓存。
16. **注册需要邮箱验证码**：6 位验证码服务端生成、哈希落库、10 分钟过期、单次使用、限 5 次尝试、60 秒发送间隔；配置 `ATOMS_SMTP_*` 后通过内置零依赖 SMTP 客户端（465/587 + STARTTLS）真实发信，未配置时走明确标注的「演示通道」在页面上显示验证码（流程与校验完全一致）。竞赛模式同样更稳：模型给出的无效配色/版式会被清洗并用有效方案补齐，而不是让整次生成失败。
17. **版本时间线与一键退回**：多次修改后的项目出现「版本」按钮，打开时间线抽屉——每版的名称、时间、当前标记一目了然，点「选用」随时退回；已发布链接不受影响。抽屉里还有**对比模式**：任意两版并排双栏实时渲染，肉眼直接看区别。
18. **发布 2.0 闭环**：发布页访客除了「有用」还能留言（文本写入 SQLite，实时回显在弹层与工作室统计里）；统计面板聚合**团队自检健康分**（由最近一次交互自检+版式体检折算成 0-100 分）；已发布页面注入 OpenGraph 标签，分享到微信/QQ 时显示模型写的标题与描述。
19. **团队建议的下一步**：每次生成/迭代完成，Adrian（增长）、David（数据）、Sarah（SEO）等角色的真实结论会自动变成可点击的建议 chips——点一下就把「按 Sarah 的建议改一版：…」填进输入框，迭代循环由团队自己推动。

## 实现与取舍

- 服务端零依赖（`node:http` + `node:sqlite`），生成时把需求分两次发给兼容 OpenAI 的接口，只接受 JSON；名字、价格、标题和八位角色的依据都来自模型返回。依据必须是页面正文里的原句，对不上就整版丢弃，不退回预制文案。
- 预览里的预约、购物袋、任务、分数等交互写在编译产物里，提交结果留在那台浏览器的本地存储；项目、版本、消息、发布、积分、浏览量和模型密钥留在 SQLite。密钥不会下发到页面，界面上只显示前后几位。
- 界面参考 Atoms 的工作流：暗色营销首页、胶囊导航、居中输入框、登录后进入三栏工作室（项目 / 对话流 / 预览台）、预览与发布分开。
- 竞赛三方案、点选改写与手动改字共享“先复制一版再写”的版本模型，任何改动都不会覆盖历史版本。
